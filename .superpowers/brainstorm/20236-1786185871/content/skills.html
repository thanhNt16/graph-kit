Session Skills — 8 Total

Skills installed into .claude/skills/ by gk init, invoked via /gk:*

gk:init-graph
Purpose: Generate a graph.yaml from a template
Input: --template diamond (optional, agent suggests if omitted)
Output: graph.yaml in project root
Flow: Pick topology → ask inputs → bind default agents → write YAML
Model: sonnet (interactive, needs judgment)
gk:brainstorm
Purpose: Refine graph.yaml via dialogue
Input: Existing graph.yaml
Output: Updated graph.yaml
Flow: Ask clarifying Qs → suggest agent/model choices → update node config → add constraints/loops
Model: sonnet (conversation)
gk:validate
Purpose: Gate check before compile
Checks: Syntax · Schema · Topology contract · Agent binding · Refs exist · depend_on acyclic · Evidence keys · Loop exit conditions · Constraint types
Output: PASS/FAIL with findings list
Model: haiku (mechanical, cheap)
gk:compile
Purpose: graph.yaml → .workflow.js
Flow: Parse YAML → resolve topology template → inject agent prompts → expand subgraph refs → generate workflow script
Output: .claude/workflows/{name}.workflow.js
Model: sonnet (code generation)
gk:run
Purpose: Execute compiled workflow
Flow: Invoke Claude Code Workflow tool with compiled script
Output: Workflow execution (agents run, evidence collected)
Model: varies per node (set in graph.yaml)
gk:evidence
Purpose: Report what the graph produced
Input: Run name
Output: Markdown evidence report
Content: Node results, evidence keys, verdict, timing, token usage
Model: haiku (formatting)
gk:status
Purpose: Show current graph run state
Output: Terminal-friendly status (running/complete), node states, pending nodes
Model: none (reads state files)
gk:visualize NEW
Purpose: Render graph.yaml as a visual diagram
Input: graph.yaml (auto-detected)
Output: .graphkit/diagrams/{name}.excalidraw
Also: Opens in browser (rendered via excalidraw skill pipeline)
Shows: Nodes (color by model tier), edges (depend_on), loops, evidence flow, subgraph boundaries
Model: sonnet (visual reasoning)

gk:visualize — Diagram Details

What Gets Rendered

  • Nodes — boxes labeled with agent name + role
  • Node color — coded by model tier (opus=purple, sonnet=blue, haiku=green, fable=orange)
  • Edges — arrows from depend_on relationships
  • Loop indicators — circular arrow on nodes with internal loops, with stop condition label
  • Subgraph boundaries — dashed rectangle around composed templates
  • Evidence flow — dotted arrows showing which keys flow between nodes
  • Topology badge — label showing the canonical shape name

Excalidraw Integration

  • Uses excalidraw-diagram skill as dependency
  • Output: .graphkit/diagrams/{name}.excalidraw
  • Editable in Excalidraw app (excalidraw.com or local)
  • Re-render to PNG on demand
  • Auto-opens in browser after generation
  • Color palette matches GraphKit brand (not default excalidraw colors)
  • Persists alongside graph.yaml — diagram is a project artifact

Typical Session Flow

/gk:init-graph --template diamond → graph.yaml created
/gk:visualize → see the graph structure
/gk:brainstorm → refine nodes, add loops
/gk:visualize → see updated structure
/gk:validate → gate check
/gk:compile → .workflow.js generated
/gk:run → execute graph
/gk:evidence → view results

Visualize is called multiple times — after init, after brainstorm changes — so the user can see the graph evolve before committing to a run.
