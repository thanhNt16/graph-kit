ClaudeKit Engineer — Reuse Map

What to adopt directly, adapt, or skip from claudekit-engineer

✅ Adopt Directly

Kit install mechanism
claude/ → .claude/ copy pattern, metadata.json deletions tracker, .ck.json user config, settings.json hook wiring
Hook architecture
Fail-open (.cjs), PreToolUse/PostToolUse/SubagentStart/Stop events, hook naming conventions, per-event scope
Agent definition format
Markdown + YAML frontmatter in claude/agents/, model/temperature/mode fields, Claude Code auto-discovers them
Skill SKILL.md contract
Frontmatter (name, description, when_to_use, user-invocable, disable-model-invocation), references/ directory pattern
Validation CI scripts pattern
check-skill-descriptions, check-skill-cross-refs, check-skill-routing — same architecture, adapted to graph-specific lint rules
Skill routing rules
domain routing + workflow routing decision trees in claude/rules/ — adapted to graph topology selection
portable-manifest.json
Provider path migration tracking for multi-harness support (Claude, Codex, Gemini, Cursor)
Release pipeline
commitlint + husky + semantic-release pattern, release-manifest checksums, Discord webhook

🔧 Adapt for GraphKit

settings.json hooks
Replace scout-block/privacy-block/simplify-gate with graph-state-guard/evidence-persist/lease-enforce. Same event slots, different hook logic.
Rules content
Replace development-rules, primary-workflow with graph-authority, agent-binding, topology-routing. Same claude/rules/ mechanism.
Domain routing
ClaudeKit routes to ck:cook/ck:test. GraphKit routes to gk:validate/gk:compile based on graph state (has graph.yaml? validated? compiled?)
.ckignore → .gkignore
Same SIZE-based blocking concept, scoped to graph artifacts (.graphkit/runs/, .graphkit/diagrams/)
Environment resolver
7-tier env var hierarchy is directly reusable. GraphKit skills that call APIs (excalidraw render) benefit from this.
Skill-native task management
Hydration/sync-back pattern for graph runs — track which nodes completed in plan files, survive compaction

⏭️ Skip — Not Relevant

90+ domain skills — GraphKit has 8 graph-engineering skills, not a general-purpose dev kit

Agent Teams (experimental) — Claude Code workflows handle parallelism natively, no need for multi-session teams

commands_data.yaml — Deprecated in claudekit, we never need it

GEMINI.md / multi-provider prompts — Not in v1 scope, add via portable-manifest later
Subagent init hook — Workflow tool handles subagent context, not hooks

Dev rules reminder hook — Graph-specific rules replace generic dev rules

Plan format kanban hook — Graph uses evidence files, not kanban plans

Cook/orchestration skills — GraphKit has its own graph-driven orchestration, not cook-based
