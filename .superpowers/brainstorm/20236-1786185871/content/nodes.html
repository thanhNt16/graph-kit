Enhanced Node Binding

Model tiering, dependencies, tools/skills, constraints, and internal loops per node

graph.yaml — Enhanced nodes section
apiVersion: graphkit.dev/v2
kind: Graph
metadata:
  name: security-audit-with-research

topology: diamond

inputs:
  repo_path: { type: string, required: true }
  scope: { type: array, default: ["src"] }

nodes:                          # rich per-node config
  scouter:
    agent: Software Architect
    model: opus                   # opus | sonnet | haiku | fable
    objective: |
      Analyze the codebase architecture.
      Map attack surfaces, entry points, data flows.
      Produce a prioritized list of files to audit.
    tools: [Read, Glob, Grep, Bash]  # available tools
    skills: [sequential-thinking]  # loaded from .claude/skills/
    refs:                          # reference docs loaded into context
      - path: docs/security-standards.md
        purpose: "OWASP top 10 checklist"
      - path: docs/architecture.md
        purpose: "system architecture context"
    depend_on: []                  # no deps = starts immediately
    loop:                           # internal loop until done
      enabled: true
      stop_when: valid_evidence_found
      max_rounds: 3
      exit_condition: |
        Stop when attack surface map has ≥ 3 concrete
        code examples with file:line references.
    constraints:                    # optional per-node guardrails
      - max_files: 50
      - no_write: true              # read-only node
    evidence: [attack_surface, file_priorities]

  worker:
    agent: Code Reviewer
    model: sonnet
    objective: |
      Audit assigned files for security vulnerabilities.
      Check OWASP patterns, injection points, auth bypass.
    tools: [Read, Grep]
    skills: []
    refs:
      - path: docs/security-standards.md
        purpose: "OWASP checklist"
    depend_on: [scouter]         # waits for scouter output
    loop: { enabled: false }
    constraints:
      - assigned_only: true         # only touch assigned files
      - max_findings_per_file: 10
    evidence: [findings, severity, remediation]

  verifier:
    agent: QA Engineer
    model: haiku                 # cheap model for verification
    objective: |
      Verify each finding has valid file:line evidence.
      Reject findings without concrete code references.
    tools: [Read, Grep]
    depend_on: [worker]

  synthesizer:
    agent: Security Engineer
    model: opus                   # top tier for final judgment
    objective: |
      Merge verified findings into prioritized report.
      Assess exploitability, propose fixes.
    tools: [Read, Write, Bash]
    refs:
      - path: docs/security-standards.md
      - path: .graphkit/evidence/
        purpose: "all upstream evidence"
    depend_on: [verifier]          # sequential: verify before synthesize
    evidence: [report, verdict, executive_summary]

limits:
  max_workers: 5
  budget_tokens: 500000

evidence:
  required_keys: [report, verdict]
  format: markdown

Node Binding Fields

Identity
  • agent — kit agent name
  • model — opus/sonnet/haiku/fable
  • objective — what this node does
Context
  • tools — allowed tools
  • skills — loaded kit skills
  • refs — reference docs + purpose
Flow Control
  • depend_on — wait for these nodes
  • loop — internal loop-until-done
  • evidence — what this node produces
Guardrails
  • constraints — per-node rules
  • no_write, max_files, assigned_only...

depend_on Controls Parallelism

Example — fanout with mixed deps: 
nodes:
  researcher:
    depend_on: []            ← starts immediately (parallel with planner)
  planner:
    depend_on: []            ← starts immediately (parallel with researcher)
  worker-a:
    depend_on: [planner]     ← waits for planner, runs parallel with worker-b
  worker-b:
    depend_on: [planner, researcher]  ← waits for BOTH
  reviewer:
    depend_on: [worker-a, worker-b]   ← barrier: all workers done
Topology template resolves depend_on into parallel() vs sequential calls.
Nodes with empty deps start together. Nodes sharing the same dep run in parallel. Nodes depending on multiple sources wait at a barrier.
