Graph YAML Schema

The user-facing graph definition that gk compile transforms into .workflow.js

graph.yaml — Full Schema
apiVersion: graphkit.dev/v2
kind: Graph
metadata:
  name: my-security-audit
  description: Full security audit with adversarial verification

topology: diamond              # one of 6 canonical names

inputs:                        # what the user provides
  repo_path:
    type: string
    required: true
  scope:
    type: array
    items: string
    default: ["src/routes", "src/middleware"]

agents:                        # graph node ↔ kit agent binding
  scouter: Software Architect
  worker: Code Reviewer
  synthesizer: Security Engineer
  verifier: QA Engineer

limits:                        # safety caps
  max_workers: 5
  max_iterations: 3
  max_findings: 50
  budget_tokens: 500000

evidence:                      # what the graph must produce
  required_keys: [summary, findings, verdict]
  format: markdown

topology_config:               # topology-specific params
  fanout:
    strategy: per-item          # one agent per scope item
    isolation: worktree         # each worker gets own worktree
  reduce: dedup+rank
  verify:
    template: adversarial-verification   # subgraph!
    survive_threshold: 2
    refuters: [QA Engineer, Security Engineer]
  stop_when: all_verified && no_critical_open

hooks:                         # lifecycle hooks
  on_node_complete: evidence-persist
  on_fanout_dispatch: lease-enforce
  on_graph_complete: report-generate

outputs:                       # where results go
  evidence_dir: .graphkit/evidence/
  report: .graphkit/reports/{name}.md

What Changed from v1

v1 workflow.yaml

  • Full node/edge graph definition
  • 8 node types with per-node config
  • Edge conditions, retry, on_error
  • State merge policies per field
  • gk CLI owns the runtime
  • Expression engine for routing
  • ~60 lines of YAML minimum

v2 graph.yaml

  • Topology name + config params
  • Agent role binding (4-6 roles)
  • Subgraph composition via template refs
  • Limits and evidence declarations
  • Claude Code workflows own runtime
  • Template handles routing logic
  • ~20 lines of YAML for common cases

Key shift: v1 asked users to define every node and edge. v2 asks users to pick a topology, bind agents, and configure params. The template handles the graph structure.

Per-Topology Config Keys

diamond: fanout.strategy, fanout.isolation, reduce, verify (subgraph), synthesizer
classify-and-act: classifier, routes[].handler, routes[].condition, fallback
adversarial-verification: producer, refuters[], survive_threshold, adjudicator
loop-until-done: scouter, worker_batch, stop_rule (dry_rounds | budget | count), dedup
generate-and-filter: generators[], rubric, keep_top, dedup_keys
tournament: candidates[], judge, rounds (optional — auto until champion)
