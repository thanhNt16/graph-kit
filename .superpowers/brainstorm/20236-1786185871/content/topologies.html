6 Canonical Topologies

Each topology is a parameterized .workflow.js template. Templates compose via subgraph references.

1. Diamond (fan-out → reduce → synthesize)
         ┌──────────────┐
         │   Scouter    │
         └──────┬───────┘
       ┌────────┴────────┐
       │   Fan-out (N)   │
       └──┬────┬────┬───┘
      ┌───┴┐ ┌─┴──┐ ┌┴──┐
      │ W1 │ │ W2 │ │W3 │
      └──┬─┘ └─┬──┘ └─┬─┘
       ┌──┴─────┴─────┴──┐
       │    Reduce (code)  │
       └────────┬─────────┘
         ┌──────┴──────┐
         │  Synthesizer  │
         └──────────────┘
Workflow: pipeline(items, fanout, reduce, synthesize)
Use: Code review, research, migration
2. Classify-and-Act
         ┌──────────────┐
         │  Classifier  │
         └──────┬───────┘
       ┌──┬────┼────┬──┐
       ▼  ▼    ▼    ▼  ▼
      ┌──┐┌──┐┌──┐┌──┐┌──┐
      │H1││H2││H3││..││Hn│
      └──┘└──┘└──┘└──┘└──┘
Workflow: agent(classify) → route → agent(handler)
Use: Triage, routing by type/complexity
3. Adversarial Verification
         ┌──────────────┐
         │   Producer    │
         └──────┬───────┘
       ┌──┬────┼────┬──┐
       ▼  ▼    ▼    ▼  ▼
      ┌──┐┌──┐┌──┐┌──┐
      │R1││R2││R3││Rn│  ← refuters (fresh context)
      └──┘└──┘└──┘└──┘
       ┌──┴────┴────┴──┐
       │  Adjudicator  │
       │ ≥2 survive?   │
       └──────┬───────┘
         ✓ kept  ✗ rejected
Workflow: agent(produce) → parallel(refuters) → adjudicate
Use: Security audit, fact-check, code review
4. Loop Until Done
      ┌─────────────────┐
      │    Scouter       │
      └────────┬────────┘
               ▼
      ┌─────────────────┐
      │   Worker batch   │◄──┐
      └────────┬────────┘   │
               ▼            │
      ┌─────────────────┐   │
      │  Dedup + check   │   │
      │  new? → loop     │───┘
      │  dry? → exit      │
      └────────┬────────┘
               ▼
      ┌─────────────────┐
      │   Synthesize      │
      └─────────────────┘
Workflow: while (!dry) { agent(scout) → parallel(work) → dedup }
Use: Discovery, bug sweeps, exhaustive search
5. Generate-and-Filter
       ┌─────────────────┐
       │  N Generators    │
       └────────┬────────┘
                ▼
       ┌─────────────────┐
       │  Score + Dedup   │  ← code, not agent
       │  (rubric filter) │
       └────────┬────────┘
                ▼
       ┌─────────────────┐
       │  Keep top-K      │
       └─────────────────┘
Workflow: parallel(generators) → score(dedup) → keep(K)
Use: Naming, design variants, ideation
6. Tournament
       ┌─────────────────┐
       │  N Candidates    │
       └────────┬────────┘
                ▼
       ┌─────────────────┐
       │ Pairwise rounds   │◄──┐
       │ A vs B → winner   │   │
       └────────┬────────┘   │
                ▼            │
       ┌─────────────────┐   │
       │ One champion?    │───┘
       │ No → next round  │
       └────────┬────────┘
                ▼
       ┌─────────────────┐
       │  Ranked output   │
       └─────────────────┘
Workflow: round(candidates) → while(n>1) { pair(judge) }
Use: Ranking, eval scoring, taste calls

Composition Example: Diamond + Adversarial Verification

Each fan-out worker in a diamond can itself be an adversarial-verification subgraph. The YAML references templates by name:

topology: diamond
fanout:
  template: adversarial-verification
  workers: [Code Reviewer, QA Engineer]
  refuters: [Security Engineer, Performance Analyst]
reduce: dedup+rank
synthesizer: Software Architect
stop_when: all_verified && no_critical_open
