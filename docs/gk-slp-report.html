GraphKit — SLP Orchestration

Implementation report · 2026-09-27 · gk 0.3.0 working tree (unreleased)

Origin. vhlam's Supervisor–Lead–Peer article identifies three orchestration failure modes this work addresses: pre-solve (main solves the problem before delegating, leaving subagents only confirm/reject), the parachute (an early design choice silently becomes a constraint for every later agent), and plan immunity (findings from the people doing the work can't change the plan). SLP's answer is operational, not cosmetic: roles are responsibilities + authority + escalation paths, dissent is a right gated on evidence, and the orchestration itself is reviewed by telemetry.

What shipped

MechanismKindWhat it does
assumptions: schema New node field — declared challengeable premises, kept separate from mandatory constraints. Materialized into the agent's ## Challengeable assumptions section: peers may reopen them with evidence. Kills the parachute: the first agent's design choice is a labeled premise, not an invisible constraint.
owns: schema Glob-declared write scope per node (["src/chute/**"]). Materialized as ## Owned scope; validateGraph emits an owns-overlap advisory when two same-wave writers' scopes can collide. Edit rights gate writes; reads stay open — challenge rights preserved.
role: supervisor schema Read-only cross-scope review node. Materializer forces the read/grep/glob toolset regardless of constraints. Reviews assumptions-of-A vs behavior-of-B; emits CHALLENGE freely; never writes code. eval-gate contract preserved; other role strings get a non-blocking unknown-role advisory.
CHALLENGE verdict contract Third node outcome beside ok/fail: a result may end with CHALLENGE: <node-id|plan> — <evidence>. Orchestrator records gk run node <id> --status challenge, then adjudicates: decision-changing → re-dispatch the challenged owner with the finding under ## Challenged premise; equally-valid → note in report; noise → ignore. Dissent is a right, never an obligation.
Steering contract hub list surfaces live node ids mid-wave; human corrections relayed via hub send <node-id>; direction changes written to the run report and evidence dir so downstream nodes see them through shared state, not just the steered peer's inbox.
gk run analyze cli Better-SLP telemetry over the ledger: escalation hit-rate (advisor-fired → subsequent ok), repeated-failure detection, unadjudicated challenges, loop stop-reasons, and evidence-gated suggestions — question-form, never alarms.
Finding.severity guard warn-severity findings surface in gk validate output without blocking graph agents/waves/validate — previously every finding was fatal.

Testing caught one real bug: listRunIds/resolveRun accepted any directory name while readRunMeta enforced the YYYYMMDD-HHMMSS-* shape — a malformed run dir resolved then failed cryptically. Fixed via shared RUN_ID_PATTERN; stray dirs are skipped and bad args get a clean RUN_NOT_FOUND.

Dispatch architecture (also shipped this session)

Native subagent dispatch replaced the omp -p child-process path:

  • gk graph agents materializes .omp/agents/gk-<node>.md — frontmatter bakes name, description, node model, constraint-derived tools (CamelCase→snake_case), autoloadSkills; stale gk-* files pruned.
  • pi kit agents now carry name/description frontmatter → omp's native task discovery sees them.
  • Waves dispatch as one task({context, tasks[]}) batch — in-process, parallel, async delivery, agent:///history:// artifacts, hub cancellation.
  • gk_dispatch_agent retained only for timeout_ms hard-kill budgets (process-group SIGTERM→SIGKILL) and advisor escalations.
  • Fixed while here: waves payload was silently dropping node constraints.

Explicit non-goals

Per the article's own warning — "dissent is a right, not an obligation" — no mandatory review nodes, no challenge quotas, no role-play personas, no new topology. Everything composes into custom.

Caveats

  • Uncommitted — 92 modified/untracked files in working tree.
  • Sessions hold the kit version loaded at start; running sessions need restart to see new semantics.
  • 9router (scout/sonnet routes) had a multi-hour outage during this session; first research wave failed on connectivity. Implementation wave ran clean on the default task agent.
