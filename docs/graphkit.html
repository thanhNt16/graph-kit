Getting Started

Installation & Setup

GraphKit installs as a single standalone binary or via source build. Initialize the kit into your repository to configure host-native agents, skills, hooks, and rules.

1. Install Prebuilt Binary
# macOS Apple Silicon curl -fsSL https://github.com/thanhNt16/graph-kit/releases/latest/download/gk-darwin-arm64.tar.gz \ | sudo tar -xz -C /usr/local/bin # Linux x64 curl -fsSL https://github.com/thanhNt16/graph-kit/releases/latest/download/gk-linux-x64.tar.gz \ | sudo tar -xz -C /usr/local/bin gk --version
2. Or Build From Source (Bun)
# Clone and build git clone https://github.com/thanhNt16/graph-kit.git cd graph-kit bun install && bun run build:bin # Move executable to PATH cp dist/gk /usr/local/bin/gk chmod +x /usr/local/bin/gk
3. Initialize Kit in Your Project
# Install kit into an existing repository: cd /path/to/your-project gk init # → .claude/ (Claude Code) gk init --target cursor # → .cursor/ (Cursor) gk init --target opencode # → .opencode/ (OpenCode) gk init --target codex # → .codex/ (Codex CLI) gk init --target pi # → .omp/ (Pi / OMP) # Or materialize a workflow from the template gallery: gk template materialize audit-pr --params '{"task":"the auth module"}' --use gk validate # check active graph against 9 DAG rules
Graph Architecture

Eleven Canonical Topologies

Workflows are built from eleven proven topological patterns. Each topology defines a specific execution flow — from parallel reduction and adversarial verification to iterative loops and tournaments.

Diamond
fan-out → reduce → synthesize
Split work to N parallel workers, reduce with deterministic logic, synthesize with a lead agent.
→ code review · security audit · research
Classify-and-Act
route 1 → 1 handler
Classifier inspects input, routes to exactly one specialized handler with fallback.
→ triage · ticket routing · escalation
Adversarial Verification
produce → refute → adjudicate
Producer emits items. Independent refuters with fresh context challenge each proposal.
→ security audit · correctness check
Loop Until Done
scout → work → dedup → repeat
Scout discovers items, workers process, dedup against seen. Loops until stop criteria or cap.
→ bug sweep · test coverage · discovery
Generate-and-Filter
generate N → keep best K
Generators produce diverse candidates. A rubric scores in one deterministic pass to select top-K.
→ naming · architecture options · design
Tournament
pairwise elimination
Candidates compete in pairwise judged brackets until one clear champion emerges.
→ ranking solutions · eval benchmarking
Memory-Augmented
wrapper: any topology + curator
Wraps any base topology. A curator agent interleaves memory extraction, expiration, and injection.
→ long-running tasks · multi-step builds
Custom DAG
arbitrary DAG via depend_on
Define arbitrary node dependencies. GraphKit automatically computes execution waves.
→ bespoke agent pipelines
SDD Flow
spec → design → dev → review
Spec-driven development flow. Brainstorm → plan → parallel implementation → multi-perspective review.
→ feature development · SDD
Superpowers Flow
brainstorm → plan → loop
Structured brainstorming, task planning, execution, and verification loops.
→ autonomous engineering cycles
Research & Build
scout → research → build
Deep scouting and literature research before writing code. Architectural decisions grounded first.
→ novel architecture · exploration
Declarative Schema & Node Binding

Per-Node Contracts & Static Gating

Every node binds its own configuration: model tier (opus, sonnet, haiku, fable), tool allowlists, reference files, loop bounds, advisor escalation triggers, and expected evidence outputs. gk validate enforces 9 static checks before anything runs.

graph.yaml
apiVersion: graphkit.dev/v2 kind: Graph metadata: name: security-audit topology: custom nodes: scouter: agent: Software Architect model: opus objective: Map attack surfaces tools: [Read, Glob, Grep] constraints: - no_write: true evidence: [attack_surface] fixer: agent: Code Reviewer model: haiku objective: Fix identified security defects depend_on: [scouter] loop: enabled: true stop_when: evidence found max_rounds: 3 advisor: model: fable after_failed_rounds: 1 max_calls: 2 evidence: [patch] evidence: required_keys: [attack_surface, patch]
9 Static DAG Validation Gates
# Run before compilation or dispatch: gk validate # 1. Syntax: Clean YAML parsing # 2. Schema: graphkit.dev/v2 schema conformance # 3. Topology: Canonical shape rules (diamond, etc.) # 4. Agent Binding: Agent fragments exist in .omp/agents/ # 5. References: Referenced ref paths exist on disk # 6. Acyclic: depend_on forms valid DAG without cycles # 7. Evidence Keys: Node evidence matches graph declaration # 8. Loop Exits: stop_when, gate_evidence, or max_rounds set # 9. Constraints: tools_allowlist and no_write rules PASS: 9 validation gates satisfied
Execution Architecture

Dual Execution Runtimes

One graph specification, two execution paths. /gk:execute provides transparent, interactive wave-by-wave dispatch across all 5 host targets. /gk:run compiles graphs into native Claude Code Workflow scripts.

ADVISOR ESCALATION

Autonomous Tier Escalation

When a looping worker encounters repeated failed rounds, GraphKit dispatches a read-only advisor at a stronger model tier (e.g., fable), injects its diagnostic guidance into the node objective, and retries the original worker.

WORKTREE ISOLATION

Parallel Worktree Merging

Passing --worktree isolates each write-capable node in its own git worktree branch. At the wave barrier, branches are reconciled and merged cleanly before dependent waves begin.

Fault Tolerance

Run Ledger & Checkpoint Resume

Failed or interrupted runs do not restart from scratch. The ledger tracks every node dispatch in .graphkit/runs/<id>/. gk run resume derives a pending-only subgraph, reattaches upstream evidence as references, and guards against git graph drift.

1. Reconcile
passed nodes ∩ on-disk evidence → satisfied
2. Derive
pending-only subgraph · upstream artifacts → refs
3. Validate
static checks guarantee valid structural DAG
4. Child Run
executes pending nodes with resumes: chain
Checkpoint Resume Workflow
# Start a graph run: gk run start # → opens ledger in .graphkit/runs/<run-id>/ # Subagent executions update ledger status: gk run node <run-id> scouter --status passed --evidence '{"attack_surface":"..."}' gk run node <run-id> fixer --status failed --round 2 # Replay and resume failed or interrupted runs: gk run resume <run-id> # derives pending graph + starts child run gk run resume <run-id> --dry-run # preview reconciliation without modifying state gk run resume <run-id> --from-node fixer # re-execute a specific node and its dependents # Drift protection: # If graph.yaml was edited since run start, resume is safely blocked: RESUME_GRAPH_DRIFT: graph modified. Use --force or commit changes.
Durable Intelligence

Project Memory & Code-Graph Bridge

GraphKit turns execution history into project assets. The memory compiler consolidates run ledgers into durable patterns, while the CBM MCP bridge enables fast code-graph queries without requiring a separate graph database.

PROJECT MEMORY

Pattern Mining & Suggestions

Consolidation analyzes run ledgers across five pattern families: node sequencing, evidence co-occurrence, failure recurrence, graph reuse, and advisor escalation repeat.

gk memory consolidate --runs 20 gk suggest # ranked workflow recommendations gk recall "auth tokens" # retrieve contextual memory
CBM CODE GRAPH

LSP-Backed Graph Queries

Bridge to Codebase Memory MCP for multi-language semantic code search, caller/callee tracing, and direct Cypher queries directly within workflow nodes.

CLI Surface

Comprehensive Command Reference

GraphKit provides 15 top-level command groups covering the full graph engineering lifecycle.

gk init [--target <host>]
Install agents, skills, hooks, and rules into the project for the target host.
gk validate [file]
Run 9 static DAG checks against graph.yaml or the active session graph.
gk compile [file]
Compile graph.yaml into a standalone .workflow.js for Claude Code.
gk gate [file]
Evaluate required evidence criteria and tree freshness: MERGE or BLOCK verdict.
gk evidence <add|list|get|report>
Manage content-addressed evidence blobs, provenance markers, and HTML reports.
gk run <start|node|end|resume|status>
Manage run ledgers, track node status, and replay interrupted runs via checkpoint resume.
gk template <list|materialize|pack>
Package and materialize reusable workflow templates from the gallery.
gk graph <list|switch|show|topologies>
Manage session graphs and inspect canonical topology definitions.
gk memory <consolidate|recall|suggest>
Mine run ledgers into reusable patterns and ranked workflow suggestions.
