OMP Orchestration Adoption — Feature Report

Historical report (2026-09-28). Snapshot of the orchestration-adoption milestone. The CLI surface has since evolved: the compile/workflow.js runtime is removed (gk run + gk exec is the only execution path), the built-in CBM bridge commands are gone (external MCP is the integration), and host support is Claude Code + Pi. Current surfaces: graphkit.html · README.

Adopts the reliability and contract machinery of the OMP orchestration design doc that graph-kit lacked — dispatch intent before launch, landed-vs-reported lifecycle, stale-run takeover, resume judgment carryover, enforced evidence stamping, recorded challenge dispositions, merge-protocol hardening — without importing the parts the doc itself defers (SQLite, adapter layer, fencing). Verified end-to-end by a live CLI demo below (real output, /tmp/gk-orch-demo).

What shipped

CapabilityLayerBehavior
Dispatch intentcligk run dispatch <node> --attempt N --via task|extension [--pid] writes dispatch.jsonl before launch; extension auto-writes it too (pid included). A crashed coordinator can now distinguish "dispatched but quiet" from "never dispatched".
landed lifecycleschemaTraceLine.landed {at, commit} + gk run land <node> --commit. reported (status ok) vs landed (integrated) are now separable facts.
require_landedgateevidence.require_landed: true → gk gate BLOCKs on ok-but-unlanded nodes; unlanded names them.
Stale-run takeovercligk run take --from <id> reconciles the dead run, refuses if its recorded pids are alive (TAKEOVER_BLOCKED), clears .active, stamps takes_over via a .takeover handoff file that survives a failed startRun. .active now created with wx (atomic).
Resume reconciliationcliresume returns unresolved[] (dispatched, never resolved) instead of silently re-dispatching; pending nodes inherit unadjudicated challenges + last advisor event as ## Resume context in their objective.
Evidence supersessionschemaMarker gains superseded; gk evidence invalidate --key marks premise-disproved evidence absent for the gate even when the tree fingerprint is still fresh.
Strict freshnessgatefreshness: strict now BLOCKs markerless (unknown) evidence with a warning naming the keys — closes the hand-written-evidence hole.
Challenge dispositionscontract--notes "disposition=accept|modify|reject|defer reason=…"; CHALLENGE: plan suspends for the human via the existing gate machinery (node challenges stay orchestrator-adjudicated). One shared DISPOSITION_PATTERN in ledger.ts serves resume and analyze.

Analyze metricsclichallenges.{total, adjudicated, dispositions} + nodes.integration_failures.

cook-plan templateclitemplates/gallery/cook-plan.gk.yaml: plan → loop{implement,test} (max_rounds 3, gate_evidence, no_progress_limit 2) → eval-gate → integrate. eval-gate promoted to a known role.

Live demo flow — real output

Executed against bun src/index.ts in a scratch repo with two nodes (build → audit, require_landed: true, strict freshness). Script: /tmp/gk-orch-demo.sh.

1–2. Materialize agents

$ gk graph agents graph.yaml
{"status":"ok","data":{"agents":{"build":"gk-build","audit":"gk-audit"},
 "dir":"/tmp/gk-orch-demo/.omp/agents"}}

$ head -6 .omp/agents/gk-build.md
---
name: gk-build
description: "Graph node 'build' (implementer) — Implement the feature per plan"
model: "sonnet"
---

3–6. Run, dispatch intent, stamped evidence, traced node

$ gk run start --graph graph.yaml
{"status":"ok","data":{"id":"20260928-053018-orch-demo","dir":"…","graph_sha256":"37c8a787…"}}

$ gk run dispatch build --attempt 1 --via task   # intent BEFORE launch
{"status":"ok","data":{"run":"20260928-053018-orch-demo","node":"build"}}

$ gk evidence add impl.md --key impl-report --node build
{"status":"ok","data":{"key":"impl-report","artifact":"impl-report/95cc8b42….md",…}}

$ gk run node build --status ok --evidence impl-report --attempt 1
{"status":"ok",…}

7. Challenge with recorded disposition

$ gk run node audit --status challenge \
    --notes "disposition=accept reason=assumption disproven, re-dispatching"
{"status":"ok",…}   # adjudication is a ledger fact, feeds analyze.dispositions

8–11. Gate blocks unlanded → land → re-stamp → MERGE

$ gk gate graph.yaml          # before landing
{"status":"fail","error":{"code":"GATE_BLOCK",
 "details":{"unlanded":["build","audit"],"stale":["impl-report"],…}}}

$ git commit -m "merge" && gk run land build --commit $SHA && gk run land audit --commit $SHA
$ gk evidence add impl.md --key impl-report   # re-stamp post-merge
$ gk gate graph.yaml          # after landing + re-stamp
{"status":"ok","data":{"verdict":"MERGE","unlanded":[],
 "freshness":{"impl-report":"fresh","audit-findings":"fresh"}}}

12. Run end — orphan scan

$ gk run end --status merged
{"status":"ok","data":{…,"orphaned_worktrees":[],"orphaned_branches":[]}}

13–16. Crash → take → resume

# coordinator dies mid-dispatch: .active + dispatch.jsonl left, no trace line
$ gk run status
{"status":"ok","data":{"active":"…/20260928-053019-orch-demo","active_age_ms":149,…}}

$ gk run take --from 20260928-053019-orch-demo
{"status":"ok","data":{"taken_from":"…-053019-…","unresolved":["build"],
 "pending":["audit","build"],"active_cleared":true}}

$ gk run resume <id> --dry-run
{"status":"ok","data":{"resumed":false,"reason":"DRY_RUN",
 "unresolved":["build"], ← "dispatched but quiet" is visible, not re-blind-fired
 "pending":["audit","build"],…}}

17–18. Analyze + invalidate

$ gk run analyze
{"status":"ok","data":{"nodes":{…,"integration_failures":0},
 "challenges":{"total":0,"adjudicated":0,"dispositions":{}},…}}

$ gk evidence invalidate --key impl-report --note "premise superseded"
{"status":"ok","data":{"key":"impl-report","superseded":true}}
$ gk gate graph.yaml
{"status":"fail","error":{"code":"GATE_BLOCK",
 "details":{"missing":["impl-report"],…}}}   # superseded evidence counts as absent

Command reference

CommandPurpose
gk graph agents <graph>Materialize .omp/agents/gk-<node>.md (frontmatter + model/tools) — pi only; orchestrator runs it once per graph.
gk run dispatch <node> --attempt N --via task|extension [--pid]Record dispatch intent before launch.
gk run node <id> --attempt N --notes "disposition=…"Trace lines carry attempt + adjudication.
gk run land <node> --commit <sha>Stamp integration commit on the ok line.
gk run take --from <id>Reconcile a dead coordinator's run; refuses on live pids.
gk run statusNow includes active_age_ms.
gk run resume <id>Carries unresolved[] + challenge/advisor context into the derived graph.
gk run endReports orphaned_worktrees + orphaned_branches.
gk evidence add <f> --key k --node nStamped evidence (required under strict freshness).
gk evidence invalidate --key kMark evidence superseded → gate treats as absent.
gk gateEnforces strict freshness, superseded, require_landed.
gk run analyzeDispositions + integration_failures metrics.

Deliberately not built

  • SQLite store — JSONL ledger is single-writer and covers today's access patterns.
  • Herdr/Orca adapter abstraction — omp task/hub + gk_dispatch_agent IS the platform layer; revisit at a second backend.
  • Per-spawn timeout on native task — runtime lacks it; timeout_ms nodes route to the extension's process-group kill.
  • ≤2-writer cap, fencing controller, persistent supervisor, cross-worktree mailboxes, escaped-defect reopening, token-cost estimation.
