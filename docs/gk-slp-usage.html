GraphKit SLP — How to Use

Challengeable premises, ownership scopes, supervisor review, evidence-driven replans — all driven by one graph.yaml.

1 Declare fields on nodes

Three new optional fields go on a node. All compose into topology: custom — no new topology needed.

nodes:
  build-handoff:
    agent: implementer
    model: sonnet
    objective: Implement seamless handoff between cells
    owns: ["src/net/handoff/**"]        # write scope — edit rights
    assumptions:                          # challengeable premises
      - "edge layer keeps the connection stable"
      - "pending inputs drain before state transfer"
    constraints: [{ no_write: false }]   # mandatory — never challengeable
    evidence: [handoff-report]

  replication-worker:
    agent: implementer
    owns: ["src/net/repl/**"]
    depend_on: [build-handoff]
    evidence: [repl-report]

  audit:
    agent: code-reviewer
    role: supervisor                         # read-only cross-scope review
    objective: Check handoff assumptions against replication behavior
    depend_on: [build-handoff, replication-worker]
    evidence: [audit-findings]
FieldMeaningEffect
assumptionsWhat we currently believeMaterialized into the agent's ## Challengeable assumptions — peers may reopen with evidence
constraintsWhat must holdNever negotiable; enforced at dispatch
ownsWhat you may write## Owned scope in agent; owns-overlap advisory on same-wave collisions; reads stay open
role: supervisorRead-only cross-scope reviewForced read/grep/glob toolset; emits CHALLENGE freely; doesn't gate the wave
timeout_msHard wall-clock kill budgetRoutes the node to gk_dispatch_agent process-group kill instead of native task

2 Run it

gk graph agents graph.yaml
→
gk run start --graph graph.yaml
→
skill gk-execute drives waves
→
gk run end

graph agents materializes .omp/agents/gk-<node>.md — the frontmatter that lets omp's native task tool dispatch each node. Re-run it if the graph changes mid-run. From then on the gk-execute skill dispatches one task({context, tasks[]}) batch per wave — you don't write dispatch code.

3 Challenge — evidence reopens a premise

A peer that finds a declared assumption wrong ends its output with the terminal line:

CHALLENGE: build-handoff — input queue still draining at transfer, see repl-report §3

The orchestrator records gk run node <id> --status challenge, adjudicates, and re-dispatches the challenged node's owner with the finding appended under ## Challenged premise. The graph re-routes — it doesn't die.

Dissent rule: challenge is a right gated on evidence (reproduction, citation, measurement), never an obligation. "I would have done it differently" is noise; "here's the trace that shows the premise fails" is a challenge.

4 Steer mid-wave

hub list                            # live node ids
hub send replication-worker "skip the legacy path, use baseline v2"

Direction changes are recorded in the run report and evidence dir — downstream nodes see them through shared state, not just the steered peer's inbox.

5 Analyze — Better-SLP telemetry

gk run analyze              # active run, else most recent
gk run analyze <run-id>     # specific run

Returns per-run metrics:

  • Escalation hit-rate — advisor-fired → did the node then pass?
  • Repeated failures — same node failing N times at similar durations = premise problem, not transient
  • Unadjudicated challenges — a challenge raised and never answered
  • Loop stop-reasons — gate / judged / no_progress / exhausted
  • Suggestions — question-form, grounded in observed data only

This is the telemetry loop that tells you whether a mechanism earns its tokens or should be removed.

Rules of thumb

Use forDon't use for
