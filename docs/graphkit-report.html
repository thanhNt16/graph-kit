Architecture
How gk, templates, and Claude Code fit together

GraphKit is a three-layer system. Templates define the graph. The gk CLI is the deterministic state machine. Claude Code Agent Skills are the bridge — they tell Claude how to drive the loop.

Claude Code
The intelligence layer. Reads the contract, performs the work (code, analysis, commands), submits structured evidence. Never decides edges or limits.
Agent Skills
The protocol bridge. SKILL.md files installed by gk template install tell Claude exactly how to call gk and what evidence to return.
gk CLI
The state machine. Owns transitions, leases, checkpoints, merges, and evidence. Deterministic — no model, no agent, no API key.
Quick Start
From zero to a running workflow in Claude Code
1

Install the template — this copies SKILL.md into your project

cd apps/gk && bun install && bun run build
gk template install templates/orchestrator-worker

This creates .claude/skills/orchestrator-worker/SKILL.md — Claude Code discovers it automatically.

2

Use the skill in Claude Code

User: /orchestrator-worker Implement the search feature

Claude Code loads the skill, reads the authority protocol, and starts the gk loop.

3

Claude drives the loop automatically

# What Claude does internally (per the skill's authority protocol):
gk workflow start orchestrator-worker --inputs '{"objective":"Implement search","tasks":"..."}'
gk workflow next orchestrator-worker --json
gk workflow submit orchestrator-worker '{"summary":"planned","items":[...]}' --lease LEASE_1 --work-item item-1
# ... for each dispatched item, Claude spawns subagents for the work ...
4

Inspect evidence after completion

gk workflow graph orchestrator-worker --format mermaid
gk evidence report orchestrator-worker --json
