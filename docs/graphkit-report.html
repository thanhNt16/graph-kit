Quick Start

Install from Source

GraphKit isn't on npm yet. Clone, build, and install as a global gk command. Requires Bun and Claude Code.

1. Clone & build
# Clone the repo git clone https://github.com/user/graph-kit.git cd graph-kit/apps/gk # Install deps + build bun install bun run build # → dist/index.js (executable, with shebang) # Run the full gate to verify bun run ci:local # → typecheck + lint + build + 105 tests
2a. Install globally (npm link)
# From the apps/gk directory: npm link # If you have a conflicting 'gk' alias # (e.g. gk → gitk), remove it from ~/.zshrc: unalias gk 2>/dev/null # Verify — should show GraphKit help: gk --help gk graph list --json
2b. Or: standalone binary
# Build a standalone binary (no runtime needed): bun run build:bin # → dist/gk (58MB, self-contained) # Install to your PATH: cp dist/gk /usr/local/bin/gk chmod +x /usr/local/bin/gk # Verify: gk --help gk graph list --json
3. Install the kit + use it
# Install the kit into your project (agents, skills, hooks, rules): cd /path/to/your-project gk init # Or scaffold a new project from scratch: gk new --dir my-project cd my-project # Define, validate, compile a graph: gk validate graph.yaml --json gk compile graph.yaml --json # → .claude/workflows/{name}.workflow.js gk graph inspect diamond # → see topology config keys # Inside Claude Code, skills auto-discover from .claude/skills/: # /gk-init-graph /gk-validate /gk-compile /gk-eval /gk-recall
Architecture

Three Layers, Clean Boundary

gk CLI validates and compiles. Claude Code executes. The kit template connects them. No custom state machine — Claude Code's native Workflow tool owns the runtime.

Graph Topologies

Seven Canonical Shapes

Each topology is a parameterized .workflow.js template. They compose — a diamond's fan-out can embed an adversarial-verification subgraph, or wrap the whole thing in a memory-augmented layer.

Diamond
fan-out → reduce → synthesize
Split work to N parallel workers, reduce with deterministic code, synthesize with one high-tier agent.
→ code review · research · migration
Classify-and-Act
route 1 → 1 handler
Classifier inspects input, routes to exactly one handler. Fallback for unmatched inputs.
→ triage · routing · escalation
Adversarial Verification
produce → refute → adjudicate
Producer emits items. Independent refuters with fresh context challenge each. Survivors pass threshold.
→ security audit · fact-check
Loop Until Done
scout → work → dedup → repeat
Scout discovers work, workers process, dedup against seen. Loop until K consecutive empty rounds.
→ discovery · bug sweep
Generate-and-Filter
generate N → keep best K
Multiple generators propose candidates. Rubric scores in one deterministic pass. Keep top-K.
→ naming · ideation · design
Tournament
pairwise elimination
Candidates compete in pairwise judged rounds. One champion emerges.
→ ranking · eval scoring
Memory-Augmented v2.1
wrapper: any topology + curator
Wraps any of the 6 base topologies. A Memory Curator agent interleaves at cadence — extract, consolidate, expire, inject-or-null.
→ long-running graphs · cross-run memory

Memory Subsystem v2.1

Graph-Backed Memory with ACT-R Forgetting

Evidence flows through the memory-persist hook into OKF markdown files. A Memory Curator agent curates at cadence — extract, consolidate, resolve, expire. Recall fetches ranked memories for the next node. Silence is first-class.

evidence write→ memory-persist.cjs→ .graphkit/memory/*.md→ Curator (cadence)→ gk:recall→ next node
ACT-R FORGETTING

Memories decay by salience = relevance × connectivity × reactivation (14-day half-life). Below threshold → expired (retained for audit, never deleted).

recent + relevant + connected → 0.72 keep stale + unused + isolated → 0.08 expire
NULL INTERVENTION

The Curator's default is silence. It only injects a reminder when it will change the next decision. Selective injection beats always-on.

injection_decision: null // rationale: "no constraint violation // detected, staying silent"
Eval-Gate Subsystem v2.1

Evidence-Based Merge Gate

Any topology can bind an eval-gate terminal node. The gate reads evidence and decides MERGE or BLOCK — the rubric is code, not a model opinion.

WORK_PRODUCT MODE

Completeness Check

Checks every required_keys value exists and is non-empty (strict) or present (lenient). Pure code — no model call.

findings: "ok", test_results: "ok" → MERGE findings: "ok", test_results: "missing" → BLOCK
MEMORY MODE (LETTA 2×2)

Abstention-Weighted

Four axes: adherence, retrieval, generalization, hygiene. Confidently answering from stale memory is penalized more than admitting ignorance.

staleAnsweredFrom: 3 → penalty -0.3 admittedIgnorance: 3 → bonus +0.15
evidence files→ scoreWorkProduct+ scoreMemory (2×2)→ MERGE/ BLOCK
