# GraphKit v2.1 — Memory + Eval-Gate Subsystems (Design)

**Status:** Draft for review
**Date:** 2026-08-08
**Extends:** [GraphKit v2 — Graph Engineering Kit for Claude Code](./2026-08-08-graphkit-v2-design.md)
**Relationship:** Companion spec. v2's 16-task implementation plan is untouched. v2.1 adds two subsystems that plug into v2's existing kit template, compiler, and runtime without modifying the 6 shipped topology templates.

---

## Goal

Turn GraphKit's evidence directory from an append-only log into a **queryable, self-curating memory** (Subsystem 1: Memory), and give every compiled graph an optional **evidence-based merge gate** with a public, deterministic eval harness (Subsystem 2: Eval-Gate). Both address gaps the v2 spec left open: v2 has no cross-run state, no knowledge-graph store, no persistent agent learning, and no eval harness or quality rubric (v1's headless replay was dropped in v2 with no replacement).

**Key research claims the design rests on:**
- *"Memory is a process, not a store."* / *"If no process is accountable for memory truth, it's an append-only log wearing a knowledge-base costume."* (Memanto)
- *"Behavioral state decay — information still in context no longer exerts reliable control over behavior."* (arXiv 2607.08716) — bigger context windows do not fix this.
- *"The null intervention is an explicit action."* Selective injection beats passive exposure, always-on injection, and Mem0-style retrieval (arXiv ablation: +8.3pp Terminal-Bench 2.0).
- *"If the harness isn't public, the number is an ad."* (Memanto) — eval harnesses ship in the kit, runnable, deterministic.
- *"An agent that confidently answers from a stale memory is worse than one that says 'I don't have that.'"* → abstention-weighted scoring.

## Decisions (locked during brainstorming)

1. **Form:** companion v2.1 spec, extends v2 by reference. v2 plan untouched.
2. **Memory backing store:** the `codebase-memory-mcp` graph (labeled-property graph, Cypher-queryable, transactional reads).
3. **Integration model (Approach C — Hybrid):** Memory as a wrapper topology (`memory-augmented`); Eval-Gate as a reusable terminal **node role** bindable in any topology.
4. **Memory write path:** **OKF-only** — memory is OKF markdown at `.graphkit/memory/`, which `codebase-memory-mcp` indexes via `index_repository` into its graph (semantic + similarity + Cypher, with free `nomic-embed-code` embeddings; auto-sync watcher reindexes on change). No write API, no C work. (Dual-write was originally considered but rejected: `codebase-memory-mcp` is a compiled C binary — `DeusData/codebase-memory-mcp`, MIT, v0.9.0 — making a write-API extension disproportionately costly.)

## Architecture: Extension Model

v2.1 adds the following to v2's kit template (installed alongside v2's components by `gk init`):

| Component | v2.1 addition | v2 baseline |
|---|---|---|
| Agents | **Memory Curator** (8th) | 7 |
| Skills | **`gk:recall`**, **`gk:eval`** (9th, 10th) | 8 |
| Hooks | **`memory-persist.cjs`** (4th) | 3 |
| Topology templates | **`memory-augmented.workflow.js`** (7th — a wrapper) | 6 |
| Node roles | **`eval-gate`** (terminal, bindable, not a topology) | — |
| Schemas | `memory.schema.json`, `eval-gate.schema.json` | graph/node/topology schemas |
| Eval | `.graphkit/golden/` harness + rubric package | — |

### Ingestion path — no server changes

`codebase-memory-mcp` already indexes markdown files into a semantic + similarity + Cypher graph (`nomic-embed-code` embeddings bundled; emits `SEMANTICALLY_RELATED` / `SIMILAR_TO` edges). Memory enters that graph by indexing `.graphkit/memory/` — **no C development, no binary rebuild, no redistribution:**

- **One-time:** index the memory directory as a cbm project — `codebase-memory-mcp cli index_repository '{"repo_path": ".graphkit/memory", "name": "graph-kit-memory"}'` (or the `index_repository` MCP tool). `gk init` does this when memory is first enabled.
- **Ongoing:** cbm's **auto-sync file watcher** detects new/changed OKF files and reindexes incrementally (XXH3 content-hash; only changed files). `memory-persist.cjs` therefore only writes OKF — indexing is automatic and asynchronous.
- **Query:** `search_graph` (semantic vector + BM25 + name/file patterns) and `query_graph` (Cypher) against the `graph-kit-memory` project.

Runtime coupling: the `codebase-memory-mcp` MCP server must be configured in the user's Claude Code session — documented prereq (`gk init` checks and warns, fail-open). If cbm is absent, the memory subsystem degrades to OKF-file-only (recall scans files directly, no semantic edges).

## Subsystem 1 — Memory

### 1.1 Memory graph schema

Node label **`Memory`** on the `codebase-memory-mcp` graph, as a labeled-property graph queried via Cypher (`query_graph`). Properties:

| Property | Type | Notes |
|---|---|---|
| `id` | string | Stable; OKF filename stem |
| `type` | enum | `status` \| `knowledge` \| `procedural` \| `subgoal` \| `experience` |
| `content` | text | The memory body |
| `project` | string | `codebase-memory-mcp` project scope |
| `run_id`, `node` | string | Provenance — which run / which graph node produced it |
| `created_at`, `valid_from`, `valid_to` | ISO-8601 w/ offset | Temporal graph (UTC, tz-aware — see §3.5) |
| `last_used_at`, `use_count` | ts / int | Reactivation signal for ACT-R scoring |
| `salience` | float | Curator-assigned |
| `expired` | bool | Active-forgetting flag |
| `superseded_by` | id ref | Temporal chain |

**Edge types** project a MAGMA-style multi-graph over the same `Memory` nodes:

| Graph | Edge types |
|---|---|
| Semantic | `RELATES_TO`, `DERIVES_FROM` |
| Temporal | `SUPERSEDES`, `VALID_AT` |
| Causal | `CAUSED_BY`, `ENABLED` |
| Entity | `ABOUT → Entity` |

A single `Memory` node lives in all four graphs simultaneously; retrieval chooses traversal per the query (fused multi-signal).

### 1.2 Ingestion path (single-write)

- **Canonical write:** OKF markdown at `.graphkit/memory/<id>.md`. YAML frontmatter mirrors the `Memory` props; body holds `content`. Diffable, shareable, OKF-exportable. This is the **only** write — the source of truth.
- **Graph derivation:** `codebase-memory-mcp` indexes `.graphkit/memory/` (via `index_repository`, kept fresh by auto-sync). cbm contributes **semantic** (`SEMANTICALLY_RELATED`) and **similarity** (`SIMILAR_TO`) edges for free; **temporal** and **causal** dimensions are encoded in frontmatter (`valid_from` / `valid_to`, `caused_by`) and queried via Cypher predicates; **entity** links surface via tags / `[[wikilinks]]` the indexer recognizes.
- **Why not direct writes:** `codebase-memory-mcp` is a compiled C binary with no generic memory write API; extending it is disproportionately costly (Decisions §4). Indexing OKF is the native, zero-cost path.

### 1.3 Memory Curator agent (8th)

```yaml
---
name: Memory Curator
description: Curates the run's memory graph — extract, consolidate, resolve, expire, decide injection
model: opus                      # judgment-heavy: inject-or-silent, conflict resolution, salience
graph_roles: [curator, injector]
evidence_keys: [memory_delta, injection_decision, expired_memories]
source: synthesized (Memanto + MAGMA + EvoMemKG + Genesys patterns)
---
```

Runs at cadence inside the `memory-augmented` topology. Each fire observes the recent trajectory window (node evidence since last fire) plus the current memory graph, then performs the Memanto lifecycle:

1. **Extract** — distill new `status` / `knowledge` / `procedural` / `subgoal` / `experience` memories from recent node evidence.
2. **Consolidate** — dedup, merge near-duplicates.
3. **Resolve** — supersede contradictions (`memory_supersede`), link entities (`ABOUT`), establish causal/temporal edges.
4. **Expire** — active forgetting (§1.6).
5. **Decide injection** — emit a concise reminder to inject into the next action node, **or an explicit null intervention** (silence is a first-class action, not a default — the trained discipline from arXiv 2607.08716).

The action node's base instructions, tools, and decoding are unchanged; the reminder is optional injected context (transient).

### 1.4 `gk:recall` skill

Any node may call `/gk:recall` to query the memory graph. Fused multi-signal retrieval (the Mem0 finding — fused beats any single signal):

- **Semantic:** `search_graph` (vector + BM25) over `content`.
- **Temporal:** filter by `valid_from`/`valid_to` + traverse `SUPERSEDES`; honors an `as_of` parameter.
- **Entity:** traverse `ABOUT` edges.

Returns top-k (`recall_topk`, default 5) ranked by `salience × recency`, each tagged with `as_of` validity. **Expired nodes are excluded from recall but retained** for audit. This is the direct counter to **behavioral state decay**: it surfaces open constraints and previously diagnosed error patterns relevant to the current node's objective — information the agent would otherwise not know to query for.

### 1.5 `memory-persist.cjs` hook (4th)

| Event | Behavior |
|---|---|
| `PostToolUse` (after node completion) | Write the node's evidence as an OKF memory file under `.graphkit/memory/`. cbm auto-sync reindexes it asynchronously. Fail-open. |

Follows v2's fail-open `.cjs` contract. On any failure (MCP unavailable, write error), it logs to `.graphkit/metrics/` and degrades gracefully — the run continues evidence-only. Also emits the four production metrics (§2.4).

### 1.6 Active forgetting (ACT-R / Genesys)

```
score = relevance(to current objective)
      × connectivity(graph degree)
      × reactivation(use_count × recency_decay)
```

Below threshold → `memory_expire(id)`: sets `expired: true`, `valid_to = now`. Excluded from recall, retained for audit; garbage-collected after a configurable TTL. This implements *"more memory is worse when it's unorganized"* (MAD benchmark) — the graph shed noise over time rather than growing unboundedly.

### 1.7 `memory-augmented` topology

A wrapper template (7th topology) that composes around any inner topology via v2's existing subgraph mechanism (v2 §2.7). The compiler injects a Memory Curator node at cadence points within the inner topology's execution:

```yaml
topology: memory-augmented
topology_config:
  inner:
    topology: diamond
    topology_config: { ... }
  memory:
    project: graph-kit-memory        # codebase-memory-mcp project name
    cadence: on_node_complete        # or every: 3
    curator: Memory Curator
    recall_topk: 5
    expire_policy: act_r
    null_intervention_allowed: true
```

**Why a wrapper topology, not always-on injection:** v2's run loop is owned by Claude Code Workflows, not by `gk` (compiler-only). Cadence injection therefore needs template-level control, which a wrapper topology provides without modifying the 6 shipped templates. Memory is opt-in: a plain `diamond` pays zero memory overhead; a `memory-augmented` wrapping `diamond` gets the full Curator loop.

## Subsystem 2 — Eval-Gate

### 2.1 `eval-gate` node role

A **terminal node role** (not a topology) bindable in any graph via `depend_on`:

```yaml
nodes:
  eval-gate:
    role: eval-gate
    agent: Code Reviewer
    depend_on: [architect, reviewer, qa]   # all producers
    eval:
      mode: work_product | memory | both
      rubric: strict
      abstention_weighted: true
      llm_as_judge:
        enabled: true
        refuters: [Code Reviewer, QA Engineer]
```

**Why a node role, not a topology:** a gate is a terminal evidence consumer, not a graph structure. A bindable node fits any topology's terminal point (diamond, tournament, loop-until-done after the loop, etc.) without forcing a wrapper. Eval is opt-in: graphs without an `eval-gate` node run exactly as in v2.

**Who scores what:** the bound `agent` (e.g. Code Reviewer) applies the `work_product` rubric to evidence keys. The `memory` mode is scored by the `gk:eval` harness logic — a code rubric over the memory graph (Letta 2×2 axes) plus the optional adversarial LLM-judge — **not** by the bound agent's domain judgment. `mode: both` runs `work_product` (bound agent) then `memory` (harness) and combines the scorecards.

### 2.2 Two eval modes

- **`work_product`** (the hanakoxbt gate): scores the evidence keys produced by the graph (`architecture_decisions`, `findings`, `test_results`, …) against rubrics — completeness, correctness, coverage. Emits a **`MERGE` / `BLOCK`** verdict plus a per-key scorecard. *"An agent finishes a change, opens it, and it goes in without a human reading it — not because anyone trusted the model, but because a gate read the evidence."* Optional **LLM-as-judge** via v2's existing adversarial-verification topology: refuter agents try to refute the verdict; the gate survives only if it passes the threshold. Judge is pinned (fixed model, temperature 0, fixed seed) for determinism.
- **`memory`** (the Letta 2×2): scores the memory subsystem itself on four axes — **adherence** (did actions respect recalled constraints), **retrieval** (were relevant memories actually fetched), **generalization** (did distilled experience transfer to new runs), **hygiene** (no stale / contradictory / duplicate memory). **Abstention-weighted**: confidently answering from stale memory is penalized more than admitting ignorance. Measured independently of code-skill benchmarks (Letta finding: SWE-bench ≠ memory skill).

### 2.3 `gk:eval` skill

Runs eval-gate logic standalone on a completed run's evidence directory → `.graphkit/reports/{run-id}-eval.md`. Public and deterministic: the rubric is code; the LLM-as-judge is pinned. *"If the harness isn't public, the number is an ad."*

### 2.4 Golden harness (restores v1's dropped replay)

v1 had a headless template-replay system; v2 dropped it. v2.1 brings the concept back, repurposed as an eval harness:

- `.graphkit/golden/`: **20–30 golden-path cases** (per Letta/Memanto guidance). Each case = input + expected evidence keys + expected memory outcomes + expected verdict.
- **Headless replay:** feed golden inputs, run/replay the compiled workflow (or replay evidence), score against expected. Ships in the kit, runnable via `bun run eval`. Reports **per-category breakdown over aggregate** (Letta finding: headline aggregates mostly measure easy categories; system spread concentrates in temporal reasoning and knowledge updates).
- **Four production metrics**, instrumented in `evidence-persist.cjs` + `memory-persist.cjs`:
  - retrieval hit rate
  - tokens per turn
  - latency per turn
  - memory growth over time

  Emitted to `.graphkit/metrics/{run-id}.json`.

### 2.5 Temporal correctness tests

Direct tests for the Memanto v0.2.8 temporal failure catalog, as unit tests in the harness:

- Tag filters must not be silently ignored on temporal queries.
- **Timestamps are UTC ISO-8601 with offset everywhere** — no tz-naive / tz-aware mixing, no midnight `as_of` off-by-one-day.
- **Idempotent supersede:** stable IDs; supersede-don't-delete → no delete-and-recreate duplicates; retrieval is deterministic (seeded).

## Data Flow

1. Compiled `.workflow.js` runs via Claude Code Workflows (v2 unchanged).
2. Each node completes → `evidence-persist.cjs` writes evidence OKF; `memory-persist.cjs` writes memory OKF **and** dual-writes the graph node (`memory_upsert`).
3. At cadence (`memory-augmented`) → Memory Curator reads the graph + recent trajectory → extract / consolidate / resolve / expire → inject-or-null.
4. Action nodes call `/gk:recall` to query the graph (fused, `as_of`-aware, expired excluded).
5. Terminal `eval-gate` reads evidence (+ memory, if `memory` mode) → rubric → `MERGE` / `BLOCK` + scorecard.
6. `gk:eval` / golden harness scores the completed run; metrics emitted to `.graphkit/metrics/`.

---

## Error Handling / Degradation

- **Hooks fail-open** (v2 contract): `memory-persist` failure never crashes a run → degrade to evidence-only, log to metrics.
- **`codebase-memory-mcp` unavailable** at runtime → `memory-augmented` degrades: skip recall/inject, set `memory=unavailable` flag; `work_product` eval still runs; `memory`-mode eval reports unavailable (does not `BLOCK`).
- **Direct-write / re-index failure** → retry once, mark affected memories `stale`; `gk:recall` surfaces the stale flag to the caller.
- **Unresolved contradiction** (two valid memories, no supersede chain) → Curator selects higher-salience, flags the pair for human review in the scorecard.
- **OKF / graph drift** → OKF is source of truth; reconcile via re-index of `.graphkit/memory/`.

## Testing (extends v2 §11) + Acceptance Criteria

**Unit:** OKF writer; dual-write sync; ACT-R scorer; temporal timestamp handling; rubric scorers; abstention weighting; idempotent supersede.

**Integration:** `memory-augmented` wrapping `diamond` end-to-end; `eval-gate` terminal on `tournament`; `gk:recall` returns expected ranked memories; incremental re-index after dual-write.

**Golden harness:** 20–30 cases headless; `MERGE`/`BLOCK` accuracy; memory 2×2 scores; regression detection across runs.

**New acceptance criteria (extend v2 AC01–AC10):**

- **AC11** — `memory-augmented` topology compiles and correctly wraps any inner topology via subgraph composition.
- **AC12** — Memory Curator node fires at the configured cadence and emits an inject-or-null decision.
- **AC13** — `gk:recall` returns ranked, `as_of`-valid memories and excludes expired nodes.
- **AC14** — `memory-persist.cjs` dual-writes (OKF + graph) and fails open when the MCP server is unavailable.
- **AC15** — active forgetting expires memories below the ACT-R threshold (excluded from recall, retained for audit).
- **AC16** — `eval-gate` node role binds as a terminal in any topology and emits `MERGE` / `BLOCK` + scorecard.
- **AC17** — `work_product` mode scores evidence keys; `memory` mode scores the Letta 2×2 with abstention weighting.
- **AC18** — optional LLM-as-judge runs via the adversarial-verification topology with pinned model / temperature / seed.
- **AC19** — golden harness runs 20–30 cases headless and reports a per-category breakdown.
- **AC20** — the four production metrics are emitted to `.graphkit/metrics/{run-id}.json`.
- **AC21** — temporal correctness tests pass (tz-aware timestamps, idempotent supersede, deterministic retrieval).
- **AC22** — graceful degradation when `codebase-memory-mcp` is unavailable (`work_product` eval still completes).

## Out of Scope (v2.1)

- **Cross-session workflow resume / checkpoints.** v2 dropped v1's checkpoint system; restoring full crash-recovery resume is a separate concern. v2.1's memory graph persists *knowledge* across runs, but a half-finished workflow is not resumable. (Future: v2.2.)
- **New canonical topologies beyond the `memory-augmented` wrapper.** The 6 v2 topologies are unchanged.
- **Multi-provider support** (Codex / Gemini / Cursor). v2 §12 defers this; v2.1 inherits the deferral.
- **The `@0xast3` source.** Unrecovered; not incorporated.

## Open Risks

1. **Auto-sync latency.** Memory enters the graph asynchronously via cbm's file watcher, not on write. A just-written memory may not be queryable for a few hundred ms within a fast-cadence run. Mitigation: `memory-persist.cjs` may shell out to `codebase-memory-mcp cli index_repository` for a synchronous reindex when cadence demands it (fail-open if the CLI is absent).
2. **Determinism of LLM-as-judge.** Pinned model/temp/seed reduces but does not eliminate variance. The rubric's code-scored dimensions are the primary signal; LLM-as-judge is an optional second refuter channel, never the sole gate.
3. **Index growth.** Memory accumulates across runs. cbm's incremental XXH3 reindex bounds per-write cost; active forgetting (§1.6) caps live memory. Long-term, expired memories can be archived out of `.graphkit/memory/` to keep the indexed set lean.
4. **Curator judgment quality.** Inject-or-null and salience are opus-tier judgment calls. The golden harness's adherence and hygiene axes are the feedback loop that tunes this.
