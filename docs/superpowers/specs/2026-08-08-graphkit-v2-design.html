GraphKit v2 — Graph Engineering Kit for Claude Code

Transform GraphKit from a standalone CLI workflow engine into a ClaudeKit-style kit template — a claude/ scaffold of agents, skills, hooks, and rules that lets users define, validate, compile, and execute graph engineering workflows through Claude Code's native dynamic workflows.

1. Architecture

Three-Layer Model

Layer 1 — Kit Template

Installed by gk init into .claude/. Contains 7 agents, 8 skills (+ vendored excalidraw-diagram), 3 hooks, 3 rules, JSON schemas, and 6 topology workflow templates.

Layer 2 — gk CLI v2

A compiler and installer. Commands: gk init, gk new, gk validate, gk compile, gk graph list/inspect. No runtime — no state machine, no leases, no checkpoints.

Layer 3 — Claude Code Runtime

Compiled .workflow.js executes via the Workflow tool. Uses agent() for single workers, parallel() for fan-out, pipeline() for streaming stages.

User Session Flow

/gk:init-graph → edit → /gk:brainstorm → /gk:validate → /gk:compile → /gk:run → /gk:evidence

2. Graph Topologies

Six canonical topologies, each a parameterized .workflow.js template. Templates compose via subgraph references.

1. Diamond fan-out → reduce → synthesize

pipeline(items, fanout, reduce, synthesize)

Fan-out work to N parallel workers, reduce with code (dedup, rank), synthesize with one high-tier agent.

Config: fanout.strategy, fanout.isolation, reduce, verify (subgraph), synthesizer

2. Classify-and-Act

agent(classify) → route → agent(handler)

Classifier inspects input and routes to exactly one handler. Includes fallback.

Config: classifier, routes[].handler, routes[].condition, fallback

3. Adversarial Verification

agent(produce) → parallel(refuters) → adjudicate

Producer generates items. Independent refuters with fresh context. Survive threshold filter.

Config: producer, refuters[], survive_threshold (default 2), adjudicator

4. Loop Until Done

while (!dry) { agent(scout) → parallel(work) → dedup }

Unknown-size tasks. Scout discovers, workers process, dedup. Stop when K rounds return nothing new.

Config: scouter, worker_batch, stop_rule, dedup, dry_threshold

5. Generate-and-Filter

parallel(generators) → score(dedup) → keep(K)

Multiple generators propose candidates. Rubric scores in one deterministic pass. Keep top-K.

Config: generators[], rubric, keep_top, dedup_keys

6. Tournament

round(candidates) → while(n>1) { pair(judge) }

N candidates compete in pairwise judged rounds until one champion remains.

Config: candidates[], judge, rounds (optional)

2.7 Subgraph Composition

Templates reference other templates as subgraphs. The compiler resolves and expands inline.

topology: diamond
topology_config:
  fanout:
    template: adversarial-verification
    refuters: [QA Engineer, Security Engineer]
    survive_threshold: 2
  synthesizer: Software Architect

3. Graph YAML Schema

3.1 Root Schema

apiVersion: graphkit.dev/v2
kind: Graph
metadata:
  name: my-security-audit
  description: Full security audit with adversarial verification

topology: diamond              # one of 6 canonical names

inputs:                        # what the user provides
  repo_path: { type: string, required: true }
  scope: { type: array, default: ["src"] }

nodes:                        # rich per-node config
  scouter:
    agent: Software Architect
    model: opus                   # opus | sonnet | haiku | fable
    objective: |
      Analyze the codebase architecture.
      Map attack surfaces, entry points, data flows.
    tools: [Read, Glob, Grep, Bash]
    skills: [sequential-thinking]
    refs:                          # reference docs
      - path: docs/security-standards.md
        purpose: "OWASP top 10 checklist"
    depend_on: []                  # no deps = starts immediately
    loop:                           # internal loop-until-done
      enabled: true
      stop_when: valid_evidence_found
      max_rounds: 3
      exit_condition: |
        Stop when attack surface map has ≥ 3 concrete
        code examples with file:line references.
    constraints:
      - max_files: 50
      - no_write: true
    evidence: [attack_surface, file_priorities]

  worker:
    agent: Code Reviewer
    model: sonnet
    depend_on: [scouter]         # waits for scouter
    loop: { enabled: false }

  verifier:
    agent: QA Engineer
    model: haiku                 # cheap model for verification
    depend_on: [worker]

  synthesizer:
    agent: Security Engineer
    model: opus                   # top tier for final judgment
    depend_on: [verifier]          # sequential barrier

limits:
  max_workers: 5
  budget_tokens: 500000

evidence:
  required_keys: [report, verdict]
  format: markdown

3.2 Node Binding Fields

FieldRequiredDescription
agentyesKit agent name from claude/agents/
modelnoOverride agent's default tier
objectiveyesPrompt injected at node start
toolsnoAvailable tools: Read, Write, Edit, Bash, Glob, Grep
skillsnoKit skills loaded into subagent context
refsnoReference docs with purpose labels
depend_onnoNode roles to wait for (empty = immediate)
loopnoInternal loop-until-done config
constraintsnoPer-node guardrails
evidencenoOutput keys for downstream nodes

3.3 depend_on Controls Parallelism

  • Empty depend_on: starts immediately with other zero-dependency nodes
  • Single depend_on: waits for that specific node
  • Multiple depend_on: barrier — waits for all listed nodes
  • Shared dependencies: nodes depending on the same source run in parallel

The compiler resolves depend_on into parallel() vs sequential calls.

3.4 v1 → v2 Shift

v1 workflow.yaml

  • Full node/edge graph definition (~60 lines min)
  • gk CLI owns runtime
  • Expression engine for routing

v2 graph.yaml

  • Topology name + config (~20 lines)
  • Claude Code Workflows own runtime
  • Template handles routing logic

9. ClaudeKit Reuse

✅ Adopt Directly

  • Kit install mechanism (claude/ → .claude/)
  • Hook architecture (fail-open .cjs)
  • Agent definition format (markdown + frontmatter)
  • SKILL.md contract
  • Validation CI scripts pattern
  • Skill routing rules
  • portable-manifest.json
  • Release pipeline (commitlint + semantic-release)

🔧 Adapt for GraphKit

  • settings.json hooks (same events, graph logic)
  • Rules content (graph-authority vs dev-rules)
  • Domain routing (graph state-based)
  • .gkignore (graph artifacts)
  • Environment resolver (7-tier hierarchy)
  • Skill-native task management

10. gk CLI v2 Commands

Kit Installation

  • gk init — install kit template
  • gk new --dir <path> — scaffold + install

Graph Lifecycle

  • gk validate [graph.yaml] — check graph
  • gk compile [graph.yaml] — YAML → .workflow.js
  • gk graph list — show topologies
  • gk graph inspect <topology> — show contract

NOT in gk CLI v2

All v1 runtime commands removed: workflow start/next/submit/execute, leases, checkpoints, events, state machine, expression engine, merges. Runtime is Claude Code Workflows only.

11. Testing Strategy

Unit Tests

  • Graph YAML parser and validator (schema, topology, node binding, acyclic deps)
  • Compiler (YAML → .workflow.js for all 6 topologies)
  • Hook logic (graph-state-guard, evidence-persist, lease-enforce)

Integration Tests

  • Full flow: init-graph → brainstorm → validate → compile → verify .workflow.js
  • Subgraph composition (diamond + adversarial-verification)
  • Agent binding validation

12. Multi-Provider (Future)

v1 scope is Claude Code only. The portable-manifest.json mechanism is adopted for future provider support (Codex, Gemini CLI, Cursor, Windsurf). Agent definitions are markdown — portable across any LLM platform.
