What's New

Two Subsystems, Clean Seam

v2.1 adds Memory and Eval-Gate as opt-in extensions. The six v2 topology templates are untouched — both subsystems layer on top.

MEMORY

🧠 Graph-Backed Memory

Evidence distilled into OKF markdown, indexed into a memory graph, recalled at cadence by a Curator agent with ACT-R active forgetting.

  • memory-persist.cjs — PostToolUse hook distills evidence → OKF
  • Memory Curator — 8th agent, opus, Memanto lifecycle
  • gk:recall — fused semantic + temporal retrieval
  • memory-augmented — 7th topology, wraps any base
  • ACT-R forgetting — salience × connectivity × reactivation
  • Null intervention — silence is first-class, not default
EVAL-GATE

🚦 Evidence-Based Gate

A terminal node role any topology can bind. Scores evidence and emits MERGE/BLOCK — not trust-based, evidence-based.

  • eval-gate node role — bind on any terminal node
  • work_product mode — required keys complete + non-empty
  • memory mode — Letta 2×2 (adherence/retrieval/generalization/hygiene)
  • Abstention weighting — confident-from-stale penalized > admitting ignorance
  • LLM-as-judge — optional adversarial-verification subgraph
  • Golden harness — headless replay, per-category pass rates

Eval-Gate Subsystem

Evidence-Based Merge Gate

Any topology can bind an eval-gate terminal node. The gate reads evidence and decides MERGE or BLOCK — the rubric is code, not a model opinion.

eval-gate node binding
nodes: worker: agent: Code Reviewer objective: Audit files evidence: [findings, test_results] eval-gate: agent: QA Engineer model: haiku # cheap gate role: eval-gate # ← terminal gate role depend_on: [worker] # must see all producers eval: mode: both # work_product + memory rubric: strict abstention_weighted: true llm_as_judge: # optional enabled: true refuters: [Code Reviewer] survive_threshold: 2
evidence files → scoreWorkProduct + scoreMemory (2×2) → MERGE / BLOCK
Scoring

Abstention-Weighted Rubrics

The memory rubric penalizes confidently answering from stale memory more than admitting ignorance. This is the key insight: silence is better than confident wrongness.

work_product mode

Checks every required_keys value exists and is non-empty (strict) or present (lenient). Pure code — no model call.

// verdict: MERGE or BLOCK findings: "ok" test_results: "ok" → MERGE findings: "ok" test_results: "missing" → BLOCK

memory mode (Letta 2×2)

Four axes: adherence, retrieval, generalization, hygiene. Abstention weighting adjusts for stale-vs-honest behavior.

// confident-from-stale penalized staleAnsweredFrom: 3 → penalty: -0.3 admittedIgnorance: 0 → bonus: 0 // honest about gaps rewarded staleAnsweredFrom: 0 → penalty: 0 admittedIgnorance: 3 → bonus: +0.15
Active Forgetting

ACT-R Salience Decay

Memories don't live forever. The Curator applies ACT-R active forgetting: salience = relevance × connectivity × reactivation. Below threshold → expired (retained for audit, never deleted).

src/eval/forgetting.ts
// reactivation = (1 + log10(1 + use_count)) × recencyDecay // recencyDecay = 0.5 ^ (ageDays / 14) ← 14-day half-life // score = relevance × connectivity × (reactivation / 2) // shouldExpire(score, 0.3) → true if score < 0.3 recent + relevant + connected → 0.72 keep stale + unused + isolated → 0.08 expire
Golden Harness

Headless Replay — Deterministic Verification

Golden YAML cases define expected verdicts. The replay runner scores them headlessly and aggregates per-category pass rates. Restores v1's dropped headless replay capability.

$ bun run eval
